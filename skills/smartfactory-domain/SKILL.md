# 생산공정 · 스마트팩토리 · AX

## 프로젝트 규약으로 못 박을 용어

일반 정의가 아니라 **혼용하면 분쟁이 나는 것들**만 다룬다. 문서 전체에서 표기를 하나로 고정한다.

| 용어 | 규약 |
|---|---|
| C/T (Cycle Time) | 공정 1건 처리 시간. **Tact Time(수요 기준 목표 시간)과 절대 혼용하지 않는다.** 표기는 "사이클타임(C/T)"로 통일 |
| OEE | 가동률 × 성능 × 양품률. **3요소의 계산식을 문서에 명시적으로 고정**한 뒤 사용 |
| PPM | 불량률 단위. **단위를 반드시 병기**(%인지 PPM인지 섞이면 1만 배 차이) |
| 공정변동성 | 동일 조건에서도 설비/환경/소재 차이로 발생하는 편차. 정의 범위를 문서에 고정 |
| 다품종 소량생산 | 품목 수 多 · 품목당 생산량 少. **개별모델 vs 통합모델**이 항상 쟁점이 된다 |
| 레시피 / 최적조건 추천 | Feed·RPM·절입량·주축부하 등 파라미터 조합 추천 |
| 앵커(선행) 공장 | 유사 사업을 먼저 수행해 방법론이 검증된 공장. 비교 기준으로 삼는다 |
| 3rd party 수집업체 | PLC/MES 데이터 수집 전담 별도 업체. 인터페이스 정의서를 별도 관리 |
| AAS | Asset Administration Shell(자산관리쉘). 표준 버전을 명시 |

## 공정 파악 순서

```
1. 제품 흐름   : 투입 → 공정1 → … → 공정N → 검사 → 출하
2. 공정별 설비 : 설비명, 대수, 제어기 기종, 통신 방식
3. 공정별 데이터: 어떤 값이 · 어디에 · 어떤 주기로 남는가
4. 현재 관리 지표: 무엇을 보고 판단하고 있는가
5. 문제 지점   : 어디서 불량·정지·편차가 발생하는가
```

## 데이터 수집 설계 확인 항목

| 항목 | 내용 |
|---|---|
| 소스 | PLC 직접 / OPC-UA / MES DB / SCADA / 파일 |
| 제어기 | 제조사·기종 (예: LS ELECTRIC XGB-XBMH2) |
| 네트워크 | IP, 포트, VLAN, 방화벽 |
| 태그 | 태그명, 타입, 단위, 정상 범위 |
| 주기 | 수집 주기, 변화 시 수집(데드밴드) 여부 |
| 보존 | 원본/집계 보존 기간 |
| 결측 | 통신 단절 시 처리 방침 |

## 실무 주의점

- **IP 정의서를 신뢰하지 말 것**(원칙 7). ping · network browsing · 물리 패널 확인으로 교차 검증한다. 문서 오류 발견 시 "문서를 고칠지 시스템을 고칠지"는 **최초 설치 시점 기준**으로 판단한다.
- **작업자 협조에 의존하는 추적(바코드 스캔 등)은 신뢰도가 낮다.** 가능하면 PLC 데이터(프로그램번호/설정값) 기반 자동 역추적처럼 **사람 개입이 적은 방식**을 우선 검토한다.
- **품질 라벨 없이 C/T만으로 "최적화"를 주장하는 것은 근거가 약하다.** 목표(C/T 표준화·예측 vs 품질 최적화)와 실제 확보 가능한 데이터가 맞는지 항상 짚는다.
- 3rd party 수집업체가 있으면 **인터페이스 정의서를 별도 관리하고 현장 실측과 문서 일치 여부를 검증**한다.

## AX 과제 캔버스

```yaml
과제명:
문제 정의:        # 현장 실제 손실 (정량)
AS-IS / TO-BE:    # 현재 방식·지표값 → 목표 방식·지표값
AI 적용 지점:     # 어느 판단을 AI가 대체/보조하는가
필요 데이터:      # 종류, 기간, 건수, 라벨 유무
데이터 확보 상태: # 보유 / 수집필요 / 확보불가
성공 기준(KPI):   # 지표 / 측정방법 / 목표치 / 측정주기
실패 시 대안:
현장 수용성:      # 작업자·관리자가 결과를 신뢰·활용할 수 있는가
```

## 단계별 게이트

```
[0] 과제 발굴   → 문제가 정량화되었는가?
[1] 데이터 진단 → 학습 가능한 양·품질·라벨이 있는가?   ← 대부분 여기서 좌초
[2] PoC        → 오프라인 성능이 기준을 넘는가?
[3] 파일럿      → 현장 조건(조도·속도·품종 변화)에서 유지되는가?
[4] 확산        → 다른 라인·품종에 이식 가능한가?
[5] 운영        → 재학습·드리프트 감지·오탐 처리 체계가 있는가?
```

게이트 미통과 시 **다음 단계로 넘어가지 말고 중단·재정의를 권고**한다.

## KPI 표 포맷

| KPI | AS-IS | TO-BE | 가중치 | 측정 방법 | 검증 책임자 |
|---|---|---|---|---|---|
| 데이터 수집 완결성 | 70% | 95% | 0.3 | 일별 수집 성공 / 계획 건수 | |
| C/T 예측 정확도 | — | 90% | 0.3 | MAPE 기준, 30일 이동평균 | |

- **AI 모델 성능 지표(F1, MAPE)와 비즈니스 지표(불량률, 시간당 생산량)를 분리**해 제시한다.
- 정부과제는 **가중치·검증방법을 사업계획서 문구와 일치**시킨다.

## 작업 지침

1. AI 적용을 제안하기 전에 **AI가 필요 없는 해법(룰 기반, 통계 관리도, 설비 개선)을 먼저 검토**하고, 그래도 AI가 필요한 이유를 명시한다.
2. 모델 제안 시 **데이터 요구량과 라벨링 공수를 함께 산정**한다.
3. PoC 성능을 현장 성능으로 약속하지 않는다. 저하 요인을 리스크로 등재한다(`risk-register`).
4. 설비명·태그명은 **절대 추측하지 않는다.** 예시는 `<설비명>` 플레이스홀더로 둔다.
5. 개선 제안 시 **현장 제약(라인 정지 불가, 설비 개조 불가, 작업자 부담)을 먼저 묻는다.**
