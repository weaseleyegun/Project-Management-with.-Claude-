# Gmail · 커뮤니케이션

## 절대 규칙

**메일 발송·전달·캘린더 초대는 초안을 먼저 보여주고 사용자 확인 후에만 실행한다. 예외 없음.**

## 메일 유형별 구조

### (A) 협의 요청

```
제목: [프로젝트명] {안건} 협의 요청 (~MM/DD)

1. 배경 (2줄)
2. 협의 필요 사항 (번호 목록)
3. 요청 사항 및 회신 기한
4. 첨부
```

### (B) 진행 보고

```
제목: [프로젝트명] 주간 진행 보고 (MM/DD)

1. 금주 완료
2. 차주 계획
3. 이슈 및 지원 요청   ← 가장 중요
4. 일정 현황 (계획 대비)
```

### (C) 이슈 통보 / 귀책 명확화

```
제목: [프로젝트명] {이슈명} 관련 조치 및 협조 요청

1. 사실 관계 (일자별, 감정 표현 배제)
2. 현재 영향
3. 당사 조치 내역
4. 협조 필요 사항 및 기한
5. 미조치 시 예상 영향 (일정/범위)
```

## 작성 원칙

- 제목에 `[프로젝트명]`과 기한을 넣는다.
- 요청 사항은 **본문 상단 5줄 이내**에 둔다.
- **일정·범위에 영향을 주는 합의는 반드시 메일로 남긴다.** 구두 합의는 "아래와 같이 이해했습니다" 형식의 확인 메일로 남긴다.
- 귀책 관련 메일은 감정 표현·추측 형용사를 제거하고 사실과 일자만 쓴다.
- **서명/직함 표기는 사용자가 명확히 확인해준 것만 사용한다.** 불확실하면 재확인한다.

## 작업 지침

1. 초안 요청 시 **수신자(고객사/사내/상급자)를 먼저 확인한다.** 톤이 완전히 달라진다.
2. 민감 메일(귀책, 지연, 추가 비용)은 **온건 버전 / 명확 버전 2가지**를 제시한다.
3. 메일 검색은 `PROJECT.md` §7의 라벨·발신 도메인·제목 키워드 기준을 사용하고, **검색 조건을 먼저 제시해 확인받은 뒤** 실행한다.
4. 회의 조율은 일시 후보·참석자·안건을 담은 초안 → 확인 → 발송 순서로 진행한다.
5. 고객사 담당자 이름·직급은 추측하지 않는다. 모르면 `⚠️확인필요`.
