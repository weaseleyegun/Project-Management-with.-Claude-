# 산출물 · 문서 검수

## 단계별 표준 산출물

| 단계 | 산출물 | 승인 |
|---|---|---|
| 착수 | 사업수행계획서, WBS, 착수보고서 | 발주처 |
| 분석 | 요구사항정의서, 현황분석서, To-Be 설계, 현장확인 체크리스트 | 발주처 |
| 설계 | 시스템설계서, DB설계서, 인터페이스정의서, 화면설계 프로토타입 | 발주처 |
| 개발 | 단위테스트 결과서, 소스, 형상관리 이력 | 내부 |
| 시험 | 통합테스트 계획서·결과서, 성능시험 결과서 | 발주처 |
| 검수 | 검수요청서, 사용자/운영자 매뉴얼, 교육자료 | 발주처 |
| 종료 | 완료보고서, 하자보수계획, 인수인계서, 감리 대응자료 | 발주처 |

## 문서 검수 체크리스트

```
[ ] 목차 ↔ 본문 제목 일치
[ ] 목차 ↔ 실제 페이지 번호 일치
[ ] 그림 목차 / 표 목차 ↔ 본문 번호·캡션·페이지 일치
[ ] 번호 표기 형식 통일 (Table N. / Fig. N 혼용 금지)
[ ] 章·節 계층 누락 없음 (2장만 소절 기재, 3~4장 누락 같은 불균형)
[ ] 용어 통일 (사이클타임 / C/T / 싸이클타임 혼용 금지)
[ ] 고객사명·시스템명·설비명 정확
[ ] 수치 단위 표기 (PPM, %, ms, MD)
[ ] 상호 참조 링크 유효
[ ] 이전 산출물과의 정합성 (요구사항ID 추적)
[ ] 파일명·버전 규칙 준수
```

오류는 **"표기 vs 실제" 대조표**로 제시하고, 원인 추정과 일괄 수정 방법을 함께 안내한다. 항목 번호를 매긴다(원칙 3).

## 인터페이스 정의서 필수 항목

```
- 인터페이스 ID / 명칭 / 방향(송신↔수신)
- 연계 방식 (REST / DB Link / File / MQ / OPC-UA)
- 주기 (실시간 / 배치 / 이벤트)
- 송신 데이터 스펙 (필드명, 타입, 길이, 필수, 설명, 예시값)
- 수신 처리 규칙
- 매핑 규칙 (계산식·변환식을 코드 수준으로)
- 예외 처리 (타임아웃, 재시도, 실패 알림)
- 인증·보안
```

> **계산식·매칭 규칙이 산문으로만 쓰여 있으면 개발자가 반드시 되묻는다.** 산식과 우선순위 규칙은 표 또는 의사코드로 못 박는다.

## 화면설계 프로토타입

- HTML로 작성한다. **원칙 4에 따라 화면 1개씩 순차 확정**한다.
- 각 화면 확정 전 검증: 콘솔 에러 / DOM 상태 / 더미 데이터 정합성.
- 요구사항ID를 화면 요소에 주석으로 매핑한다(감리 추적성).

## 파일명 · 버전

```
파일명: YYYYMMDD_{문서명}_v{버전}.{확장자}
버전  : v0.x 내부 초안 → v1.0 고객 제출 → v1.1 피드백 반영 → v2.0 승인본
```

감리·정산 대상 문서는 원본을 보존하고 임의 삭제하지 않는다. 버전을 새로 만들어 관리한다.
