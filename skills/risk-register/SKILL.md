# 리스크 · 이슈 관리

## 리스크 등록부

| ID | 리스크 | 분류 | 확률 | 영향도 | 등급 | 대응전략 | 대응계획 | 담당 | 상태 |
|---|---|---|---|---|---|---|---|---|---|

- 분류: `일정` `범위` `기술` `자원` `외부` `데이터` `현장`
- 대응전략: `회피` `전가` `완화` `수용`

## 이 도메인 상시 리스크 (신규 프로젝트 기본 검토 항목)

1. **데이터 부족·품질 불량** — AI 과제 최다 실패 원인
2. **품질 라벨 부재** — 최적화 과제의 근거 약화
3. **현장 접근 제약** — 라인 정지 불가, 야간·주말만 작업
4. **IP·설비·스키마 문서와 실물 불일치**
5. **3rd party 수집업체 일정·협조 지연**
6. **고객사 담당자 교체 / 의사결정 지연**
7. **핵심 인력 이탈** (PM/PL 공백)
8. **요구사항 무한 확장** (CR 절차 부재 시)
9. **레거시(MES/ERP) 연계 협조 지연**
10. **PoC → 현장 성능 저하**
11. **감리 지적** (추적성 매트릭스 미비)

신규 프로젝트 온보딩 시 위 11개를 검토해 해당 항목을 `PROJECT.md` §10에 초기 등재한다.

## 작업 지침

1. 이슈 보고는 **사실 / 영향 / 원인 / 조치 / 필요지원** 5단 구조로 낸다.
2. 리스크가 현실화되면 **이슈로 전환 처리**하고 등록부 상태를 갱신하도록 안내한다.
3. 지연 이슈는 **귀책 구분(당사 / 고객사 / 3rd party)**을 명확히 하고, 고객사·3rd party 귀책이면 **공문·메일 증빙 확보 필요성**을 명시한다.
4. 프로젝트 종료 시 새로 겪은 실패 패턴을 위 상시 리스크 목록에 추가하도록 제안한다.
