# 일정관리 · WBS · 진척도

## 관리 방식

- WBS는 **엑셀**로 관리한다(원칙 2). 시트명에 날짜/버전 표기 — 예: `WBS_260721`.
- **파일명 버전(v1.0.1)과 내부 이력 버전(v1.0.6)이 다를 수 있다.** 항상 내부 최신 시트/이력이 진짜 최신임을 확인한다.
- 계획 대비 지연 시 **원인을 기록하고 리베이스라인**한다. 기존 계획을 지우지 말고 버전 이력으로 남긴다.

## WBS 구조

```
L1 단계   : 착수보고 → 현장인터뷰/현행업무분석 → 요구사항정의
            → 화면/모델 설계 → 개발 → 실증 → 결과보고/감리대응
L2 산출물 : 각 단계 결과물 단위
L3 작업   : 담당자 1인이 5일 이내 완료 가능한 단위
```

| WBS ID | L1 | L2 | L3 작업 | 담당 | 시작 | 종료 | 공수(MD) | 진척률 | 선행 | 상태 |
|---|---|---|---|---|---|---|---|---|---|---|

- 상태: `대기` / `진행중` / `완료` / `보류` / `지연`
- 진척률: **0 / 25 / 50 / 75 / 100 다섯 단계만.** 임의 중간값 금지.

## 진척률 규칙

```
단계 진척률 = Σ(하위 공수 × 진척률) / Σ(하위 공수)
```

- 산출물 단계: 초안 제출 75%, **문서 승인 완료 시에만 100%**
- 개발 단계: 단위테스트 통과 75%, 통합테스트 통과 100%
- 일정 경과율과 진척률이 어긋나면(일정 80% / 진척 40%) 반드시 경고한다.

## 작업 지침

1. WBS 신규 작성 시 **L1 구성만 먼저 제안 → 승인 후 L2·L3 전개**(원칙 4).
2. **진행상황을 물을 때 낙관적으로 답하지 않는다.** 착수가 밀렸거나 마일스톤이 지연됐다면 지연 폭을 구체적으로 말한다. 예: "최소 2~3주 지연".
3. 진척 보고는 항상 3가지를 포함한다: 계획 대비 실적 / **지연 작업과 지연 일수** / Critical Path 영향.
4. 일정 재수립 시 **단축 가능 구간(병렬화·인력투입)을 먼저 찾고** 마일스톤 연기는 마지막 옵션으로 둔다.
5. 지연 원인은 다음으로 분류한다: `요구사항 변경` / `고객사 자료 미제공` / `기술 난이도` / `인력 이탈` / `선행 지연` / `현장 접근 제약` / `3rd party 지연`.
   **고객사 귀책이면 "공문/메일 증빙 확보 필요"를 명시한다.**
6. 갱신 결과는 그 자리에서 WBS 파일에 반영하고 반영 위치를 밝힌다(원칙 1).
