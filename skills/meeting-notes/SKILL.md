# 통화녹음 · 회의록

## 워크플로

```
핸드폰 통화녹음 → STT(클로바노트 등) → 회의록 정리 → meetRecord/ 저장
                                              ↓
                              원칙 1: 관련 문서 즉시 반영
```

## STT 원문 취급 — 변환 원문을 그대로 신뢰하지 않는다

| 오류 유형 | 예시 | 처리 |
|---|---|---|
| 전문용어 오인식 | "오피씨유에이" → OPC-UA | 문맥상 명백하면 교정 후 `(추정)` 표기 |
| **설비·회사·사람 이름** | 왜곡 빈번 | **교정하지 말고 `⚠️확인필요`** |
| 숫자·시각 | "일곱시" vs "17시" | **반드시 확인 요청** |
| 화자 분리 오류 | 발언자 뒤섞임 | 맥락으로 재확인, 불명 시 "발언자 불명" |
| 중복·군말 | "어… 그러니까…" | 제거 |

## 회의록 포맷

```markdown
# {프로젝트명} 회의록

- 일시: YYYY-MM-DD HH:MM (통화 N분)
- 참석: ⚠️확인필요
- 형태: 유선 통화 / 대면 / 화상

## 1. 논의사항

## 2. 결정사항
| # | 결정 내용 | 결정 주체 | 영향 |

## 3. 미결사항
| # | 안건 | 필요 정보 | 결정 기한 |

## 4. Action Items
- [ ] (P1) 작업 — @담당 — due: MM-DD

## 5. 일정 / 범위 영향

## 6. ⚠️ 확인 필요 (STT 불확실 구간)
| 원문 | 추정 해석 |
```

## 작업 지침

1. **"결정 사항"과 "논의만 된 것"을 엄격히 구분한다.** 애매하면 미결로 분류한다.
2. 일정·비용·범위 언급은 §5에 별도 정리하고 **CR 대상 여부를 판단해 표시**한다(`requirements`).
3. 숫자·날짜·금액은 원문 그대로 인용하고 해석을 병기한다.
4. 회의록 작성 후 요청 없이도 **Task 목록을 함께 출력**한다(`task-fieldcheck` 포맷).
5. **원칙 1 적용** — 회의에서 합의된 요구사항 변경·일정 변경·신규 확인사항은 회의록에서 끝내지 않고 **요구사항정의서·WBS·체크리스트에 바로 반영**한다. 반영한 파일과 항목을 응답에 명시한다.
6. 고객사 발송용이면 내부 판단·주관 코멘트를 제거한 버전을 별도 제공한다.
