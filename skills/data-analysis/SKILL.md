# 데이터 분석

## 원칙

- 원본 데이터(엑셀/CSV/쿼리결과)는 **대화창에 붙이지 않고 파일로 다룬다.**
- 분석 로직은 **재현 가능하도록 `.py`로 `_scratch/`에 저장**한다. 일회성 인라인 명령보다 파일 우선.

## 절차

```
1. 목적 확정   : 이 분석으로 어떤 의사결정을 하는가
2. 데이터 진단 : 기간, 건수, 결측, 중복, 이상값, 단위
3. 전처리      : 처리 내역 기록 (무엇을 왜 제거했는가)
4. 분석        : 기술통계 → 분포 → 관계 → 원인
5. 해석        : 현장 맥락으로 번역
6. 제언        : 실행 가능한 액션으로
```

## 데이터 진단 리포트 (분석 결과보다 **먼저** 출력)

```
- 기간: YYYY-MM-DD ~ YYYY-MM-DD (N일)
- 건수: N건 (일평균 N건)
- 결측: 컬럼별 결측률 상위 5개
- 중복: N건
- 이상값: 물리적으로 불가능한 값 (음수 온도, 0 사이클타임 등)
- ⚠️ 분석 신뢰도에 영향을 주는 항목
```

## 시각화 선택

| 목적 | 차트 |
|---|---|
| 시간 추이 | 라인 |
| 항목 비교 | 바 |
| 분포 | 히스토그램 / 박스플롯 |
| 관계 | 산점도 |
| 공정 관리 | 관리도(X-bar, R) |
| 원인 비중 | 파레토 |

파이 차트는 항목 4개 이하일 때만. 축 시작점을 0이 아닌 값으로 자르면 반드시 명시한다.

## 작업 지침

1. **상관을 인과로 서술하지 않는다.** "A일 때 B가 높다"까지만 쓰고, 인과는 검증 방법을 제안한다.
2. 그룹당 30건 미만이면 결론 앞에 표본 부족 경고를 붙인다.
3. Python은 pandas 기준, 주석은 한국어, 중간 결과 출력을 포함한다.
4. 보고 요약은 **"발견 3개 + 액션 3개"** 구조로 낸다.
5. **이 분석만으로 목표(예측 모델 구축, 원인 규명)에 도달 가능한지, 어떤 데이터가 더 필요한지를 반드시 짚는다**(원칙 5).
6. 이상값은 임의 보정하지 않는다. 보정 전에 먼저 보고한다.
