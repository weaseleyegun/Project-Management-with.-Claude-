# 신규 프로젝트 초기화

## 0. 템플릿 배치

현재 작업 디렉터리에 `CLAUDE.md`가 없으면 `${CLAUDE_PLUGIN_ROOT}/templates/CLAUDE.md`를 복사한다.
(플러그인 경로를 못 찾으면 사용자에게 플러그인 설치 경로를 묻는다.)
이미 있으면 덮어쓰지 말고, 플러그인 템플릿과 다른 점만 요약해 보여주고 갱신 여부를 묻는다.

## 1. 기존 PROJECT.md 확인

현재 디렉터리에 `PROJECT.md`가 이미 있으면 먼저 읽고 **`<TBD>`로 남은 항목만** 질문한다.
없으면 전체 항목을 질문한다.

## 2. 온보딩 인터뷰

아래 21개 항목을 **한 번에 묶어서** 사용자에게 제시한다. 한 개씩 되묻지 않는다.
사용자가 일부만 답하면 나머지는 `<TBD>`로 둔다. "지금은 건너뛰자"고 하면 `<TBD>`로 채운 `PROJECT.md`만 만들고 진행한다.

```
■ 프로젝트
  1. 프로젝트명 / 고객사(도입기업) / 수행사(공급기업)
  2. 사업 유형 (SI 구축 / 정부지원 실증 / 컨설팅 / 유지보수) — 감리 대응 필요 여부
  3. 사업계획서(제안서) 존재 여부 및 경로 — 예산·KPI·마일스톤·수행기간의 원본 근거 문서
  4. 수행 기간, 예산 규모
  5. 내 역할 (PM / PL / 실무) 과 담당 범위
  6. 이해관계자 (고객사 부서, 3rd party 데이터수집업체, 앵커공장 등)

■ 경로
  7. 로컬 작업 폴더 절대경로
  8. 공유드라이브(구글드라이브) 프로젝트 폴더 경로 — 없으면 "해당없음"
  9. git 저장소 여부. 아니면 버전관리 방식
 10. 스크래치/임시파일 폴더 위치

■ 데이터
 11. DBMS 종류·버전 (MariaDB / MS-SQL / PostgreSQL+TimescaleDB / MongoDB / Oracle)
 12. 접속정보 위치 — .env 파일 경로인가, PROJECT.md 직접 기재인가
 13. 접근 권한 (읽기전용 SELECT만? 쓰기 가능?)
 14. 데이터 소스 (PLC / OPC-UA / MES DB / SCADA / 파일)

■ 도메인
 15. 대상 공정 / 대상 설비 / 연계 시스템(MES·ERP 등)
 16. 핵심 KPI (지표 / AS-IS / TO-BE)

■ 커뮤니케이션
 17. Gmail에서 이 프로젝트 메일을 찾을 기준 — 라벨명, 발신 도메인, 제목 키워드
 18. 회의록 저장 폴더명 (예: meetRecord/)
 19. 정기 보고 주기·요일

■ 산출물
 20. 이번 프로젝트의 핵심 산출물 목록
 21. 현재 단계 (착수 / 분석 / 설계 / 개발 / 시험 / 검수)
```

**3번(사업계획서) 답변이 "있음"이면** 파일을 직접 전달받거나 경로를 받아 즉시 열어
예산·KPI·마일스톤·수행기간 항목(`PROJECT.md` §1, §6, §9)을 채운다.
"없음"이면 해당 항목은 `<TBD>`로 남기고 진행한다.

## 3. PROJECT.md 생성

`${CLAUDE_PLUGIN_ROOT}/templates/PROJECT.template.md` 구조로 `PROJECT.md`를 생성한다.
**DB 비밀번호 등 실제 값은 PROJECT.md에 쓰지 않는다.** `.env` 경로만 기재한다.

## 4. .env 점검

`.env`가 있으면 **키 이름만** 확인한다. `.gitignore`에 `.env`가 없으면 경고한다.
git 저장소가 아니면 공유드라이브 동기화 대상에서 제외하도록 안내한다.

## 5. 폴더 구조 제안

다음 폴더가 없으면 생성 여부를 묻는다. **이미 진행 중인 프로젝트에는 강제 이식하지 않는다.**
기존 배치가 다르면 실제 구조를 `PROJECT.md` §3에 기록하고, 새로 만드는 파일부터 점진 적용할지 협의한다.

```
{프로젝트명}/
├─ CLAUDE.md
├─ PROJECT.md
├─ 01_기획/          # 사업수행계획서, WBS
├─ 02_요구사항/      # 요구사항정의서, 감리ID_추적표
├─ 03_설계/          # 시스템/DB/인터페이스 정의서, 화면 프로토타입
├─ 04_개발/
├─ 05_시험/
├─ meetRecord/       # 회의록
├─ 07_보고/          # 주간보고, 단계보고
├─ 08_데이터/
│   ├─ raw/          # 원본 불변
│   ├─ processed/
│   └─ analysis/
├─ _scratch/         # .py, .sql, 덤프 — 동기화 제외
└─ 99_참고/
```

## 6. 초기 리스크 등재

`risk-register` skill의 상시 리스크 11개 중 이 프로젝트에 해당하는 항목을 골라
`PROJECT.md` §10에 초기 등재하고 사용자에게 확인받는다.

## 7. 모듈 재설정 확인

```
[ ] 공유드라이브를 안 쓰면 PROJECT.md §11에 "동기화 비활성화" 기록
[ ] DB 연동이 없으면 §4에 "해당없음" 기록
[ ] 스마트팩토리가 아닌 도메인이면, 프로젝트 고유 용어집을 §11에 추가
[ ] Gmail 라벨/검색 기준 설정 (§7)
```

## 8. 완료

생성된 `PROJECT.md` 요약을 보여주고, 원래 하려던 작업으로 넘어간다.
